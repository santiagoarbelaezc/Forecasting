1. TSMixer

TSMixer es una arquitectura de deep learning para pronosticar series temporales multivariadas, propuesta por Chen et al. Su idea central: nada de Transformers ni self-attention, solo MLPs.

DEFINICIÓN DEL TENSOR

1. Entrada del Modelo

Estructura tridimensional recibida por la red antes de pasar por las N Mixer Layers apiladas.

X ∈ ℝB × L × C
DIMENSIÓN B
Tamaño del Batch (B)
Número de series o ventanas procesadas en paralelo.
DIMENSIÓN L
Pasos Históricos (L)
Longitud de la ventana de observación pasada (ej. 96).
DIMENSIÓN C
Número de Variables (C)
Canales o características multivariadas (ej. 7).
Ejemplo Concreto: 32 series, 96 pasos históricos, 7 variables → X ∈ ℝ32 × 96 × 7
PROCESAMIENTO INTERNO

2. Dentro de cada Mixer Layer

Cada capa ejecuta en secuencia: 2D Batch Norm, Time Mixing con transposición, y Feature Mixing profundo.

Paso a

2D Batch Norm

Normaliza la representación antes de mezclar, estabilizando el entrenamiento a lo largo de las dimensiones de tiempo y características.

Paso b

Time Mixing

1 Capa FC

Primero se transpone conceptualmente la entrada de ℝB×L×C a ℝB×C×L, para que el MLP opere sobre la dimensión temporal L en vez de sobre las variables.

MLPtime(X) = Dropout(ReLU(FC(X)))

Solo una capa fully-connected, ReLU y dropout. Este MLP se comparte entre todas las variables: aprende un único patrón temporal aplicable igual a cada feature, lo cual reduce parámetros y evita sobreajuste.

X' = X + MLPtime(X)
Conexión residual directa tras el bloque temporal.
Paso c

Feature Mixing

2 Capas FC

Aquí el MLP es más profundo con dos capas FC en vez de una. Se comparte entre todos los pasos temporales: aprende cómo se relacionan las variables entre sí, independientemente del momento en el tiempo.

MLPfeat(X') = Dropout(FC(Dropout(ReLU(FC(X')))))

Residual de nuevo tras el procesamiento cross-variate:

X'' = X' + MLPfeat(X')
Conexión residual que preserva la señal previa al feature mixing.
INSIGHT DE DISEÑO CLAVE

Asimetría Intencional: MLP_time simple vs MLP_feat más profundo

El paper busca que el modelo mantenga la capacidad de los modelos lineales temporales clásicos (que funcionan sorprendentemente bien en forecasting) mientras añade la capacidad de capturar interacciones entre variables.

PROFUNDIDAD DEL MODELO

3. Apilamiento (N capas)

MixerLayer1 → MixerLayer2 → … → MixerLayerN

Cada capa adicional permite capturar relaciones más complejas, tanto temporales como cross-variate, sin agregar attention ni recurrencia.

Default habitual en implementaciones: N = 2 bloques (suficiente para la mayoría de benchmarks).
MAPEO FINAL

4. Temporal Projection

L → H

Al final, una capa Fully Connected transforma la dimensión temporal de L pasos históricos a H pasos futuros:

X ∈ ℝB × L × C → Ŷ ∈ ℝB × H × C
Ejemplo: De 96 pasos históricos a 24 pasos futuros (L=96 → H=24).

revin Reverse Instance Normalization

Si es True, normaliza cada serie individualmente antes de entrar al modelo y desnormaliza la salida. Muy útil para manejar series con escalas y distribuciones distintas.

TSMixerx Variables Exógenas

El modelo base no maneja variables exógenas por defecto. Para escenarios con información auxiliar o exógena existe la variante especializada TSMixerx (o TSMixer-Ext).

FUNDAMENTO METODOLÓGICO

6. ¿Por qué importa el diseño "todo MLP"?

El paper surge como respuesta a la pregunta: ¿realmente necesitamos self-attention para forecasting?

TSMixer reemplaza las capas de atención por operaciones lineales/MLP sobre la dimensión temporal, y demuestra resultados competitivos con Transformers, pero con muchos menos parámetros y cómputo, porque:

✕ Sin Atención

No hay Q, K, V ni softmax attention.

✕ Sin Recurrencia

Cero recurrencia (sin cuellos de botella de LSTM, GRU o RNN).

✕ Sin Convolución

No depende de filtros ni capas convolucionales 1D/2D.

✓ Simplicidad Pura

Transformaciones lineales + ReLU + normalización + residuales.
